## What we did today — complete summary

### Morning: Research and architecture session (chat only)

Full calibration architecture designed from first principles:

1. Tare lifecycle
   - Tare is setup-time only — NOT every boot
   - Measured at: first install (empty platform) + cylinder replacement
   - Normal boot reads tare_raw from config.json
   - Indian cylinder brands vary by ±700g empty weight — cannot hardcode
   - Tare re-measured on every cylinder replacement

2. Cal factor architecture — three approaches locked
   - Approach A: user inputs stamped empty weight from cylinder collar
   - Approach B: brand average bootstrap (HP/Bharat/Indane) for first install
   - Approach C: 30-day self-derived from gas consumption trend (v0.3+)
   - Bootstrap-then-refine: brand average day 0, precise cal from first cycle end
   - 30-day method uses trend line extrapolation to handle 95-98% replacement
   - Trend line slope = personalised household burn rate (not government average)

3. Cal factor variation — why it matters
   - Measured range: 100–107 raw/g = 6.5% variation = 923g error on 14.2kg
   - Causes: temperature (strain gauge resistance), mechanical creep, mounting stress
   - Must recalibrate on every cylinder replacement

4. Noise sample count decision
   - N=200 for experiments (lab accuracy, 44 seconds acceptable)
   - N=50 for production boot (~11 seconds, 10% STD error, 2× detection margin safe)
   - N=20 rejected — 16% error cuts margin below 2× minimum
   - noise_reset(int n_samples) — N as parameter, never hardcoded

5. Data intelligence roadmap locked
   - v0.3: trend line, personalised burn rate, precise cal_factor
   - v1.0: session patterns, anomaly detection, confidence intervals
   - v2.0: TFLite on QRB2210, Kalman filter, predictive refill alerts
   - v3.0: LLM agent, gas ordering API, multi-cylinder fleet management

6. Module result struct contract locked
   - Every module returns: value + quality (GOOD/DEGRADED/FAILED) + diagnosis
   - Never just bool — graduated response enables degraded operation
   - State machine reads quality and routes — never sees module internals

Key design decisions in 004:
- Modules receive raw readings from sketch.ino — never call hx711 directly
- Dependency injection: sketch.ino wires data source to logic modules
- Every module: one sample per loop() iteration, non-blocking
- TARE has 5 statuses: BUSY / RETRY / DEGRADED / SUCCESS / FAILED
  RETRY = waiting between attempts (millis-based)
  DEGRADED = all retries done, best available accepted (production use)

WAIT state redesign — physical detection replaces dumb timers:
- TARE_WAIT: consecutive reading stability check (labs(r - prev_r) < 300)
  detects stable empty scale regardless of absolute raw value
- CAL_WAIT: delta = r - tare_raw, if delta > 8000 raw → weight detected
  5 consecutive detections → advance to CAL_MEASURE
  every 5s without weight → prompts user "place 158g on scale"
- NOISE_WAIT: labs(r - tare_raw) < 300, 10 consecutive → advance

## Tomorrow's session — Experiment 005 Calibration Linearity

### What 005 proves

cal_factor computed with 158g. Is it accurate at other weights?
Load cells can have non-linear response — cal_factor at 158g may not apply at 14kg.
This must be verified before trusting the gas cylinder weight measurement.

### What to bring

- 158g known weight (already have)
- Additional known weights: ideally 300g, 500g, 1kg
- If no calibrated weights: use water + measuring cup + known container weight
  500ml water = 500g (accurate enough for linearity test)

### Experiment 005 protocol (design in chat before implementing)

1. Build 005 as new experiment folder, copy from 004
2. Tare + noise characterisation as usual
3. Cal with 158g → get cal_factor
4. Measure known weights at multiple points: 158g, 300g, 500g, 1kg
5. For each: compute expected raw vs actual raw
6. Plot linearity — if cal_factor consistent across range → linear → trustworthy
7. If cal_factor varies with weight → load cell is non-linear → need multi-point cal

### Why linearity matters for gas cylinder

```
Cal measured at : 158g
Cylinder weight : ~29,700g (full) to ~15,500g (empty)
Range ratio     : 29,700 / 158 = 188×
```

If load cell has even 1% non-linearity, error at 29kg could be:
29,700g × 1% = 297g error. Acceptable or not? Experiment 005 answers this.
