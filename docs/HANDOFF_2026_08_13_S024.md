## What Was Done This Session (S024)

### 1. Audio fix — mixer freq and buffer
**File:** `hub/main.py`
- Changed `pygame.mixer.init(frequency=44100)` → `frequency=48000`
- Changed `buffer=4096` → `buffer=8192`
- **Why:** fuzzy_horizon.mp3 is encoded at 48kHz. Wrong frequency caused SDL to resample,
  producing crackling. Small buffer caused underruns on the USB audio path.
- **Verified:** audio clean at session close, no underruns logged.

### 2. Per-node silence watchdog
**File:** `hub/ble_scanner.py`
- Added `_watchdog_per_node()` function, fired every 10s via `GLib.timeout_add_seconds`
- Threshold: `NODE_SILENCE_THRESHOLD_S` (30s) from `hub/config.py`
- Action: D-Bus `device.Disconnect()` — triggers `_properties_changed` → standard reconnect
- **Why:** global watchdog keys on `last_packet_time` from ANY node. If JB-0 healthy and
  JB-1 silent, global watchdog never fires. Per-node watchdog checks each independently.

### 3. Global watchdog threshold raised
**File:** `hub/config.py` and `hub/ble_scanner.py`
- `WATCHDOG_TIMEOUT_S`: 30s → 120s
- **Why:** with per-node watchdog at 30s, both could fire simultaneously — per-node triggers
  soft eviction + reconnect, global triggers hard adapter reset mid-reconnect. Cascade.
  120s global only fires when BOTH nodes silent for 2 minutes — genuine adapter fault.

### 4. Abort event — 4-second GATT blind window fix
**File:** `hub/ble_scanner.py`
- Replaced `time.sleep(4)` in connect worker with `abort_event.wait(timeout=4)`
- `abort_event = threading.Event()` stored in `_connect_abort_events[dev_path]`
- `_properties_changed` sets event when `Connected=False` fires during GATT window
- Worker wakes immediately, routes to `_on_connect_fail` — no phantom `_active_connections`
- **Why:** `time.sleep(4)` created a window where disconnect events had nothing to clean
  up, producing phantom connected state that prevented reconnect for 30s.

## Open Issues — Priority Order

### 1. JB-1 Supervision Timeout — Firmware (CHUNK 2) — HIGH
**Status:** NOT DONE. Design confirmed, implementation pending.

**The problem:** Default NimBLE supervision timeout is 42 seconds. If hub disconnects
without `LL_TERMINATE_IND` (crash, cable pull), JB-1 stays in ghost-connected state for
42 seconds — invisible to `btmgmt find`, not advertising. Requires operator power cycle.

**Design (confirmed in S024):**
In `comms.cpp`, add `onSubscribe` callback to `NimBLEServerCallbacks`:
```cpp
void onSubscribe(NimBLECharacteristic* pChar, NimBLEConnInfo& connInfo, uint16_t subValue) {
    if (subValue == 1 || subValue == 2) {
        pServer->updateConnParams(connInfo.getConnHandle(), 24, 40, 0, 500);
        // minInterval=24 (30ms), maxInterval=40 (50ms), latency=0, timeout=500 (5s)
    }
}
```
After this, node self-detects ghost and resumes advertising within 5 seconds of hub disconnect.

**Risk of NOT fixing:** ghost connection can still strand the node for up to 42 seconds on
any unclean disconnect.

### 2. Watchdog False Positive on Fresh Connect — MEDIUM
**Status:** Identified, not fixed.

**The problem:** `_node_last_seen` persists across reconnects (Python dict, never cleared
on disconnect). If JB-1 was last seen at T=0, reconnects at T=35s, per-node watchdog fires
at T=30s interval and sees `silent_for = 35s > 30s` — fires eviction immediately after
connect, before the node has had a chance to send a packet.

**Fix (one line):**
In `_on_connect_success`, reset the timestamp:
```python
node_id = int(node_name.split('-')[1])
_node_last_seen[node_id] = _time.time()
```
This gives the node a fresh 30-second window from the moment connection is established.

### 6. Validation Sweep Polarity Bug — LOW
**Status:** Identified, not fixed.

**The problem:** `cal_validate()` reports `measured=0.0g` for all weight points.
Root cause: `cal_to_grams()` uses `if (u <= 0.0f) return 0.0f` where `u = raw - cal.raw_zero`.
With negated ADC: `raw ≈ -100280`, `cal.raw_zero ≈ -49800`, so `u = -50480 < 0` → returns 0.

**The validation sweep is not blocking calibration correctness.** The piecewise model stored
in NVS is built from raw_refs directly — the polarity is consistent (all negated). The model
works correctly in game because `cal_to_grams` is only called from `scale.cpp` which feeds
`weight_engine`, not from validation.

**Fix:** In `cal_to_grams`, use `fabsf(u)` — or restructure to handle negative polarity.
Not urgent — defer to S025 cleanup pass.

## Reference: BLE Adapter Reset Sequence

When the adapter is wedged or after any unclean shutdown — exact order, no shortcuts:

```bash
sudo hciconfig hci0 down          # error 95 on this platform = expected, ignore
sudo hciconfig hci0 up            # error 95 on this platform = expected, ignore
sudo systemctl restart bluetooth
sleep 15                          # mandatory on Qualcomm UART — do not reduce
sudo systemctl start juice-ble-scanner
```
