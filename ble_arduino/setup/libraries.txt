=== Adding New Libraries to the Project ===

CASE 1 - Pure Python libraries (requests, numpy, flask, etc.)
--------------------------------------------------------------
Just add the library name to requirements.txt:

  /app/wheels/dbus_python-1.4.0-cp313-cp313-linux_aarch64.whl
  /app/wheels/pycairo-1.29.0-cp313-cp313-linux_aarch64.whl
  /app/wheels/pygobject-3.56.2-cp313-cp313-linux_aarch64.whl
  requests        <-- just add the name
  numpy           <-- just add the name

App Lab installs them automatically from PyPI on Run.
No wheel file needed.


CASE 2 - Libraries with system dependencies (C extensions)
-----------------------------------------------------------
These fail with "cannot open shared object file" errors.
Follow these steps:

Step 1 - Build the wheel on the host terminal:
  pip3 wheel <library-name> --wheel-dir ~/ArduinoApps/gggg/wheels

Step 2 - Find its .so dependencies:
  ldd ~/ArduinoApps/gggg/wheels/<library>.so

Step 3 - Copy missing .so files to wheels/:
  cp /lib/aarch64-linux-gnu/<missing.so> ~/ArduinoApps/gggg/wheels/
  cp /usr/lib/aarch64-linux-gnu/<missing.so> ~/ArduinoApps/gggg/wheels/

Step 4 - Add wheel path to requirements.txt:
  /app/wheels/<library>-<version>-cp313-cp313-linux_aarch64.whl

Step 5 - Add ctypes.CDLL load at top of main.py (in the lib loop):
  'libmissing.so.1',   <-- add to the existing list

Step 6 - Delete cache and run:
  rm -rf ~/ArduinoApps/gggg/.cache


HOW TO KNOW WHICH CASE?
-----------------------
Run: pip3 show <library>

- No system deps shown  --> Case 1 (pure Python)
- Has .so dependencies  --> Case 2 (C extension)

If it works fine after just adding to requirements.txt --> Case 1
If it fails with "shared object file not found"        --> Case 2
